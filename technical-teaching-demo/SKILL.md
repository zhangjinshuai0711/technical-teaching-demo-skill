# 技术交互教学 Demo

将技术材料转成学习者能解释、核算和操作的教学页面，并验证交付后实际可用。尊重用户指定的形式、篇幅、技术栈和授权，不把小演示扩大为完整课程。

## 确定这次要教什么

先读输入材料、项目约定和已有实现。只追问会改变教学目标的缺口：学习者当前基础、希望完成的任务、资料范围和交付形式。已有明确回答就直接使用，不从学历、旧对话或项目身份推断能力。

将目标写成可检查的表现，如“能手算一次更新”“能指出当前配置走的分支”“能解释某个指标的分母”。学习时长只是估计。章数、功能数和字数不能代替理解深度。

涉及推导、源码、实验或长课程时，读取 [教学设计与证据](references/teaching-and-evidence.md)。以资料清单记录来源及定位，并区分原始报告、实际实现、教学简化与分析推论。缺少源码或实验记录时缩小承诺，不补造事实。

## 先完成小闭环，再制作页面

选取能手算的固定输入，说明输入、关键中间量、输出及适用边界；用确定性检查核算结果，再把有教学价值的变量接入控件。教学模拟和结果复算不冒充真实训练或 benchmark 复现。

按学习路径组织连续正文、随文演示与自测；长课程再增加回查入口。答案手动展开，不能自动标记“掌握”。搜索、笔记、进度、原文阅读器只在目标需要时添加。

已有项目沿用其组件和工具链。新建简单静态 demo 可复制 [最小模板](assets/minimal-demo/index.html) 所在目录，按 [模板用法](assets/minimal-demo/README.md) 替换内容与计算。它是可选起点，采用原生 HTML/CSS/JS，无 CDN、无构建步骤，不要求用户安装前端依赖。不要将示例的加权评分机制套用到其他主题。

## 验收实际使用路径

交付前读取 [验收与交付](references/verification-and-delivery.md)，将适用项目落实为检查和记录。

分别检查资料覆盖、计算、交互、桌面与窄屏渲染、访问入口，以及需要时的独立语义审查。页面能打开与讲解正确是不同结论；“确认收到”不等于已掌握。

本地 HTML 默认提供可复制 HTTP 地址和可重复启动方法，并验证离线文件及解压包。服务只监听 `127.0.0.1`，仅服务交付目录。用户指定其他交付方式时遵从其选择，并说明相应限制。没有检查用户实际浏览器显示时，不能宣称已确认其屏幕结果。

结束时给出产物入口、启动与恢复方法、通过的检查及未验证范围。遇到缺失工具或失败，保留具体证据与可行替代；不以 HTTP 200、测试数量或结构映射代替完整验收。原始资料保留原位；公开分发仅包含有权分发的内容。

## 让它更好读、更抓眼

页面能用之后，可选用一层可逆的呈现升级改善可读性与吸引力；用户要求更美观、更吸睛，或要改已有课程时，读取 [呈现层](references/presentation-layer.md)。

已安装 `design-taste-frontend`（taste）且任务需要视觉方向与看图迭代时，可按其适用范围配合使用；教学证据、离线资源和已有交互约束仍以本 skill 为准。它是可选工具，未安装时直接使用本地呈现层参考，不自行联网安装或复制第三方 skill。

要点：只新增升级样式与脚本，不改课程内容与逻辑；字体按主题分场景且只用本地字体栈；首屏保留一个显示级焦点；图表只画材料里已有的数字、数轴按真实比例并标来源。改完必须回看三档截图——门控通过不代表页面没问题，叠字、错位与竖排只有看图才发现。
