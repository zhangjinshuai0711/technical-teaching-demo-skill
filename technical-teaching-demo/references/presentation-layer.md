# 呈现层：字体、首屏、图表与看图复核

用于把**已经能学**的教学页面做得更好读、更抓眼的场合。它是交付后的可选增强，不是每门课的必做步骤；内容、数据与交互逻辑不因本层而改变。

## 用可逆的升级层改，不动课程本体

每个页面只新增两个文件，并在入口各加一行引用：

```
taste-upgrade.css   # 在课程主样式之后加载
taste-upgrade.js    # 在课程脚本之后加载
```

- 除入口的两行引用外，课程 HTML、数据文件、计算逻辑与交互脚本都不改；删掉两个文件与两行引用即完全还原。
- 原样式表选择器密集时，可在升级层里用少量 `!important`，但要在文件注释中写明理由。
- **不要用脚本移动 DOM 节点做排序或布局**。需要调整视觉次序时用 CSS（`order`、`grid`、`flex`）；JS 只用于注入本层自己的图表与动效类名。已有实践：用 JS 把“标签/数值”换序，直接压坏了页面的行结构。
- 覆盖既有组件的网格或高度前，先确认那个属性是不是该组件布局的支点（把 `grid-template-columns` 改成固定高度会让整行文字叠在一起）。

## 字体按主题分场景，但只用本地字体栈

离线课程不能引网络字体。用“本地优先 + 跨平台回退”的栈；`document.fonts.check('16px "字体名"')` 只作加载状态辅助检查，不能单独证明实际使用了该字体。需要确认命中时，检查浏览器的实际渲染字体（如 Rendered Fonts 或 Chromium `CSS.getPlatformFontsForNode`），分别核对中文、拉丁字符与缺字回退。只检查 CSS 声明或加载状态时，应将实际字体命中标为未验证。

| 主题类型 | 标题 | 正文 | 说明 |
| --- | --- | --- | --- |
| 学术推导、论文精读 | 衬线栈：`Charter / Iowan Old Style / Georgia / Songti SC / SimSun / Noto Serif CJK SC` | 系统无衬线 | 公式、矩阵、图表刻度可沿用衬线；字重 600 左右 |
| 技术工程、源码、token | 无衬线紧字距：`Avenir Next / Segoe UI / PingFang SC / Microsoft YaHei / Noto Sans CJK SC` | 系统无衬线 | 数字用 `font-variant-numeric: tabular-nums` |
| 纪实取证、案例复盘 | 高对比衬线：`Iowan Old Style / Charter / Georgia / Songti SC` | 系统无衬线 | 标题字重高、字距略紧 |
| 产品与业务课程 | 黑体优先无衬线：`PingFang SC / HarmonyOS Sans SC / MiSans / Microsoft YaHei` | 系统无衬线 | 标题字距 −0.03em 左右 |

一个页面最多两族字体（通常是“衬线标题 + 无衬线正文”）。正文保持系统无衬线，避免长文阅读负担。

## 首屏

- **一个焦点**：主标题做到约 5–6vw（常见 62–84px），首屏不同时出现两个大元素。
- **通栏色调场**：给首屏一块与正文不同的色调，出血到正文边缘。窄屏取消出血（负边距在 768px 曾造成 14px 横向滚动），加断点保护。
- 原设计中的渐变改成平色；细线分隔与 1px 描边盒改成色调层级（相邻区块差一档底色）。
- 大标题折行要在两行以内；列宽不足就改回通栏，别把标题压到三行。

## 图表

- **只画材料里已经有的数字**，并标出来源（章节、原文报告、页面自带统计）。不做“看起来像数据”的装饰图，不造数。
- **数轴按真实比例并明确范围**。0.43 与 0.4350208 相差 0.0050208，约为前者的 1.17%；是否属于舍入差异必须核对原文精度，不能仅凭图判断。柱形比较从零开始；点图若放大到 0.42–0.44，应明确标注截断范围，此时两点仍相隔轴长约 25%，不能描述为“几乎重合”。
- 对比类图表共用同一比例尺，并标出倍数关系。
- 标签不得互相压盖：数值标签写在柱内或加足间距，参考线标签靠边放，避免与最高柱的数值重叠。
- 图内文字不小于 13px；图表说明写“来源 + 非本机复现”之类的边界。
- 数据优先**运行时从页面自身读取**（课程数据对象、DOM 里的时长），比在图表里重新硬编码一份数字更不容易与正文脱节；读不到数据时安静地不插入，不影响阅读。

## 动效层

- 入场：标题、正文、图表依次上移淡入，60–90ms 间隔，只触发一次。
- 控件反馈：按下、悬停、聚焦各有状态。
- 必须尊重 `prefers-reduced-motion`：关闭后内容完整可见、不发生位移。
- 动效只用 `transform` 与 `opacity`，不改变颜色体系；脚本失败时内容默认可见（入场类名由 JS 添加）。

## 看图复核（门控之后必须做）

自动检查只测被量化的东西。叠字、错位、竖排、按钮折行只有看渲染结果才能发现。改完至少看 1440 / 768 / 390 三档首屏与一两张内容页截图，并回答：焦点是否唯一、有没有重叠或遮挡、标签是否竖排/折行、图表标签是否打架、色调场边缘是否干净。

实践中最常见的四类“测不出来的”缺陷：

1. 组件被覆盖后文字叠压（改了网格或高度）；
2. 首屏一侧大片空白（图被挤到首屏之外）；
3. 标题折成三行（列宽不足）；
4. 顶栏按钮文字竖排（缺 `white-space: nowrap`）。

## 收尾

- 门控剩余项要么修掉，要么写清辩护理由：**内容信息**（如 20/24 章课程的侧栏章节号）与**交付承诺**（如离线、不引外部资源）可以保留，但要写进交付记录，不能假装已通过。
- 改完跑课程自带的测试。样式层也会影响布局断言：全量课程检查、浏览器检查与计算检查都应重跑并保留输出。
